# Dev-box gbrain ops suite

The scheduled jobs that keep the dev box's brain current, plus the systemd
user units that run them. **This directory is the source of truth**: the box
runs installed copies, in `~/.gbrain` (scripts) and `~/.config/systemd/user`
(units), so removing a checkout or worktree never breaks a timer.

The shared HTTP MCP server and its liveness probe live separately, in
[`../local-http`](../local-http/README.md).

## Install / check

```bash
deploy/local-ops/install.sh --check    # drift between repo and installed copies (exit 1 on drift)
deploy/local-ops/install.sh --dry-run  # what an install would change
deploy/local-ops/install.sh            # install/refresh; replaced files kept as *.bak-<ts>
```

Edit here, then install. Don't edit `~/.gbrain/*.sh` directly: `--check`
reports it as drift, and the next install overwrites it.

## Jobs

| Unit | Schedule | Enabled | What it does |
|---|---|---|---|
| `gbrain-daily-resync.timer` | daily 03:30 | yes | `daily-resync.sh` runs 3 phases: 1) `bulk-refresh.sh`; 2) per-repo sync of the code sources through `resync-lib.sh` (see below); 3) `gbrain embed --stale`. |
| `gbrain-libsrt-refresh.timer` | Sun 02:00 | yes | `libsrt-refresh.sh`: weekly libsrt drift refresh. |
| `gbrain-bulk-refresh.timer` | Sun 03:00 | no | `bulk-refresh.sh` on its own. It already runs inside daily-resync. |
| `gbrain-todo-refresh.timer` | daily 02:30 | no | `todo-refresh.sh`: TODO/ROADMAP refresh (opt-in). |

The daily-resync and libsrt units carry a `pool-size.conf` drop-in
(`GBRAIN_POOL_SIZE=2`), so batch jobs never crowd the shared HTTP server out of
the Supabase pooler.

### Per-repo code sync (`resync-lib.sh`)

`daily-resync.sh` syncs `CODE_SOURCES` (`swx-srtx swx-spp swx-abbe swx-opencode
swx-llmrouter`; the last three use `--strategy auto`). For each repo,
`sync_on_default_branch`:

1. records the current branch (or detached commit);
2. stashes any changes, including untracked files;
3. switches to the remote's default branch (asked via `git ls-remote --symref`,
   because a local `origin/HEAD` can be stale) and fast-forwards it;
4. runs `gbrain sync --source <id> --strategy <s> --no-pull --yes`;
5. always switches back to the original branch or commit and pops the stash.

A repo with a rebase, merge or cherry-pick in progress is skipped. A default
branch with unpushed commits can't be fast-forwarded, so it isn't synced. If the
default branch is checked out in another worktree, the job syncs a detached
`origin/<default>` instead. A stash that can't be popped cleanly is kept and
reported, never dropped.

### Markdown bulk refresh (`bulk-refresh.sh`)

This stages `.md` files from `REPOS` (`swx-srtx swx-spp`) into
`~/.gbrain-staging-bulk/<repo>/…` and imports them under the `default` source.
Repos synced with `--strategy auto` are deliberately not staged, because their
markdown already comes in through their own source.

## Not tracked here

- **`gbrain-autopilot.service` / `~/.gbrain/autopilot-run.sh`:** generated by
  `gbrain autopilot --install`. The installed copy points at a leaked test path
  (`/tmp/gbrain-install-test-…`), so autopilot is disabled. Regenerate it with
  `gbrain autopilot --install` if you want autopilot back.
- **Secrets:** `~/.gbrain/config.json` and `~/.gbrain/http.env`.
- **Database role settings:** see [`../supabase`](../supabase/role-settings.sql)
  (`bun deploy/supabase/role-settings.ts` verifies them).
